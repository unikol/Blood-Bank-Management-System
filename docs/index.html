3 Реалізація по етапах

1

Створення Azure VM

Було створено VM nik-vm-01 на Ubuntu 24.04. Під час створення стандартний size B1s був недоступний, тому було вибрано інший доступний size, зокрема B2ts/B2s.

Важлива примітка для відео: відхилення від туторіалу було через недоступність B1s у вибраному регіоні/підписці.
2

SSH і доступ до VM

Підключення до VM виконувалося через SSH / MobaXterm. Для зручної роботи також використовувався tmux.

ssh azureuser@20.126.6.252
tmux new -s azure
3

Apache/PHP/MySQL client

На VM встановлено web stack для PHP-застосунку.

sudo apt update
sudo apt install -y apache2 php libapache2-mod-php php-mysql git unzip mysql-client
sudo systemctl enable apache2
sudo systemctl restart apache2
4

Azure NSG і порт 80

Apache локально працював, але сайт спочатку не відкривався з браузера. Було налаштовано inbound rule для HTTP port 80 у Network Security Group.

Результат: сторінка Apache та Blood-Bank app відкривалися за public IP.
5

Azure Database for MySQL Flexible Server

Було створено окремий dedicated Azure database resource. Firewall rule дозволив доступ до MySQL тільки з IP Azure VM.

Public access enabled.
Firewall rule: allow-nik-vm-01.
VM public IP: 20.126.6.252 → 20.126.6.252.
SSL mode used for MySQL connection.
6

Деплой Blood-Bank-Management-System

Репозиторій було склониновано, SQL dump знайдено, застосунок скопійовано в Apache web root.

cd /tmp
git clone https://github.com/DevOps2-Fundamentals/Blood-Bank-Management-System.git
find /tmp/Blood-Bank-Management-System -name "*.sql" -type f

sudo rm -rf /var/www/html/*
sudo cp -a /tmp/Blood-Bank-Management-System/. /var/www/html/
sudo chown -R www-data:www-data /var/www/html
sudo chmod -R 755 /var/www/html
sudo systemctl restart apache2

5 Труднощі та виправлення

Проблема 1: сайт не відкривався з браузера
Було: Apache локально відповідав, але браузер показував timeout.
Причина: у Azure NSG не був коректно відкритий HTTP port 80.
Рішення: додати inbound rule для port 80 HTTP. Після цього сайт почав відкриватися за public IP.
Проблема 2: MySQL timeout / ERROR 2003
Було: MySQL client зависав або повертав Can't connect to MySQL server.
Причина: правило Azure MySQL firewall не було застосоване/збережене або доступ з VM IP не був дозволений.
Рішення: додано firewall rule для VM public IP і перевірено порт 3306.
timeout 10 bash -c 'cat < /dev/null > /dev/tcp/nik-bloodbank-mysql.mysql.database.azure.com/3306' && echo "3306 OPEN" || echo "3306 CLOSED"
Проблема 3: HTTP 500 при реєстрації
Було: PHP Fatal error: Field 'id' doesn't have a default value.
Причина: після імпорту в Azure MySQL з’явилися invisible my_row_id primary keys, а очікувані поля id/bid/reqid/donoid/bdid не мали AUTO_INCREMENT.
Рішення: ALTER TABLE: прибрати my_row_id, зробити потрібні ID поля PRIMARY KEY AUTO_INCREMENT.
Apache error.log, який допоміг знайти проблему
sudo tail -n 80 /var/log/apache2/error.log

6 SQL fix / фінальні зміни в базі

Виправлення primary key / auto_increment
ALTER TABLE hospitals
DROP PRIMARY KEY,
DROP COLUMN my_row_id,
MODIFY id INT NOT NULL AUTO_INCREMENT,
ADD PRIMARY KEY (id);

ALTER TABLE receivers
DROP PRIMARY KEY,
DROP COLUMN my_row_id,
MODIFY id INT NOT NULL AUTO_INCREMENT,
ADD PRIMARY KEY (id);

ALTER TABLE bloodinfo
DROP PRIMARY KEY,
DROP COLUMN my_row_id,
MODIFY bid INT NOT NULL AUTO_INCREMENT,
ADD PRIMARY KEY (bid);

ALTER TABLE bloodrequest
DROP PRIMARY KEY,
DROP COLUMN my_row_id,
MODIFY reqid INT NOT NULL AUTO_INCREMENT,
ADD PRIMARY KEY (reqid);

ALTER TABLE blooddonate
DROP PRIMARY KEY,
DROP COLUMN my_row_id,
MODIFY donoid INT NOT NULL AUTO_INCREMENT,
ADD PRIMARY KEY (donoid);

ALTER TABLE blooddinfo
DROP PRIMARY KEY,
DROP COLUMN my_row_id,
MODIFY bdid INT NOT NULL AUTO_INCREMENT,
ADD PRIMARY KEY (bdid);
Результат: реєстрація користувача почала працювати, вкладки сайту відкривалися без HTTP 500.
